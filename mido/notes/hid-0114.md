## Control Center investigation and bounded fix

The actual preserved ADT is D21AP / iPhone10,2 / iPhone8 Plus with
home-button-type0, not the obsolete D22AP identity in old patch comments.
Accepted HID contacts include starts near y1901..1913 followed by upward
movement. The lower screen is not entirely missing from the input stream;
exact edge calibration and UI recognizer thresholds are not proven.
Some malformed/duplicate-identity reports are still rejected as intended;
do not relax the stable0112 decoder based only on gesture symptoms.

MidoHIDTouch advertises service properties Built-In and DisplayIntegrated,
but its hand/finger events did not explicitly carry that metadata. The
custom IOHIDEventService::dispatchEvent also did not propagate Built-In.
The bundled IOHIDEvent ABI exposes separate event fields for both properties
and supports their setters; service properties and event data are distinct.
This omission is a concrete compatibility defect. Whether it is the cause
of this specific Control Center failure requires a physical test.

0114 adds four setters and changes one registration marker:
- Mark dispatched events Built-In before delivery to any client.
- Mark the hand collection DisplayIntegrated.
- Mark each finger child Built-In and DisplayIntegrated before appendChild.
- Register log now says touch registered (built-in display events).

No coordinate scaling/snapping, touch decoder/state changes, synthetic
swipes, gesture shortcuts, GPU writes, framebuffer, root or CPU changes.
Event masks, sender IDs, identities and dispatch ordering remain unchanged
except the new metadata is set before dispatch. This is NOT a proven fix.
