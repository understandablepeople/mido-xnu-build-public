# Experimental SHA256 callback adapter

mido_sha256.c adapts BearSSL SHA256 to this XNU revision's ccdigest_info
and ccdigest_ctx layout. It does not embed a BearSSL context in an undersized
XNU allocation. The original 108-byte layout retains processed bit count,
eight native-endian state words, a 64-byte pending buffer and pending count.
Compression and finalization use BearSSL's public state export/import APIs;
no BearSSL private context layout is assumed.

The descriptor exports SHA256 only. Other digest descriptors are rejected,
not silently substituted with SHA256. Its unsigned-char final callback and
the crypto table's void-pointer final callback have separate typed wrappers.
The test fixture includes the original register_crypto.h and verifies all
four callback types with C11 type assertions, without function-pointer casts.
This is an Android-target ARM64 build check, not a KERNEL=1 XNU build.
The fixture supplies the XNU-style enum declaration fallback missing from
Android sys/cdefs.h; it does not replace any crypto callback declarations.

The original entropy collector uses SHA256_CTX from libkern/crypto/sha2.h;
the fixture checks allocation size against that original definition. Tests
execute the actual Cortex-A53 adapter, including the descriptor's final
function pointer, and compare with independent Python hashlib results.
Coverage includes padding boundaries, partial blocks, multi-block updates,
context field values, empty input, zero-length update preservation, one
million ASCII a bytes, and rejection of invalid pointers, overlap, foreign
descriptors and corrupt context counters.

Input is limited to the SHA256 64-bit bit-length domain. The adapter panics
on unsupported or malformed calls; it does not return a plausible digest
after an error. It does not allocate or use FP/SIMD in the tested build.
One-shot hashing clears its temporary XNU context. As with the original
digest ABI, streaming callers own context lifetime and synchronization.

This is one component of a provider, not a complete crypto function table.
It is not registered, crypto_init is not changed, and the current image
does not contain it. HMAC, other digest algorithms, cipher interfaces,
real lock services, startup registration and a real kernel rebuild remain
separate integration work. Offline fixtures do not prove handset boot.
